# Context

`wiki_wspace init` installs harness-specific instructions and two native Agent
Skills. Copilot keeps both kinds of project customization under `.github/`:
the instruction block is in `.github/copilot-instructions.md` and skills are in
`.github/skills/<skill-name>/`. Cursor installs an always-apply rule at
`.cursor/rules/wiki-wspace.mdc` and skills under `.cursor/skills/<skill-name>/`.
Other harnesses retain their native paths.

The packaged `index.md.j2` is initialization input, not a project maintenance
surface. Initialization creates `wiki_<project>/index.md` when it is missing.
After that, the index is project-owned: humans and refresh skills edit it
directly, and `wiki_wspace update` preserves its contents (including optional
root-only `okf_version` front matter), progressive-disclosure listings, and
glossary links.

Project-local prompt templates are intentionally not installed. Refresh and
query instructions live in each native `SKILL.md`, while the longer maintenance
guide is stored under the refresh skill's `references/` directory. This avoids
adding tool prompts to the searchable semantic wiki without losing the refresh
or query workflows.

## Constraints

- Never use a project-local `wiki_engine/templates/index.md.j2` to customize an
  initialized index.
- A missing index may be recreated from the package template; an existing index
  must never be regenerated by `update`.
- Package templates must be loaded from the installed `wiki_engine` package so
  files in a target repository cannot shadow them.
- Concept notes follow OKF v0.2 front matter; subdirectory `index.md` files have
  no front matter.
